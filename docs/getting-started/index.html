Getting started

A careful first path: install the installer, confirm what is present, preview changes, install a small set of groups, and run one authorized check against a lab you control.

1. Install the installer

On Debian, Ubuntu, Kali or Mint, the recommended route is the signed APT repository:

curl -fsSL https://eergn.github.io/eergn-network-recon-installer/eergn-archive-keyring.gpg \
  | sudo tee /usr/share/keyrings/eergn-archive-keyring.gpg >/dev/null
echo "deb [signed-by=/usr/share/keyrings/eergn-archive-keyring.gpg] https://eergn.github.io/eergn-network-recon-installer ./" \
  | sudo tee /etc/apt/sources.list.d/eergn.list
sudo apt update
sudo apt install eergn-recon-installer

On other platforms, use the standalone script or clone. The full set of methods is on the installation page.

2. Confirm the package and see the groups

eergn-recon-installer --version
eergn-recon-installer --list

--list prints the nine group IDs: nmap, netcat, arp-scan, fping, mtr, dns, tls, iperf3 and bandwidth. These IDs are the values accepted by --tool.

3. Check what is already installed

eergn-recon-installer --check

--check does not need root and does not change anything. It prints a + or - for each command in every group. It exits 0 only when every command in all nine groups is present; otherwise it exits 1. If you only want to inspect a few tools, read the table and ignore the exit code as needed.

4. Preview the install commands

eergn-recon-installer --all --dry-run

The dry run prints the package-manager commands without running them. It also prints ok after each simulated package and shows a status table at the end. In a dry run those ok lines mean "the command was printed", not "the package was installed". Re-run --check afterwards to see the real state.

5. Install a focused set

Start with discovery and DNS:

sudo eergn-recon-installer -t nmap -t dns -y

-t is repeatable. -y skips the confirmation prompt. The installer refreshes the package index, installs packages one at a time, then prints a status table. Installer output is logged to a temporary file whose path is printed at the start and again if something fails.

Or use the interactive menu:

sudo eergn-recon-installer

At the prompt, enter space-separated numbers such as 1 3 5, a for all tools, or q to quit. With no options in a non-interactive shell, the installer installs all groups instead of showing the menu.

6. Run a first authorized lab check

The following sequence assumes a private lab network such as 192.168.1.0/24 that you own or are authorized to assess. Confirm the interface and route first:

ip route
ip -brief address

Discover local IPv4 neighbors with ARP. This is link-local and only sees the segment your interface is on:

sudo arp-scan --localnet

Check reachability across the lab range with fping:

fping -a -g 192.168.1.0/24 2>/dev/null

List responding hosts with Nmap's ping scan, without scanning ports:

nmap -sn 192.168.1.0/24

Inspect one host's service versions, with a conservative timing template:

nmap -sV -T3 192.168.1.10

Check DNS records for a lab name and the route to it:

dig +short A lab.example.internal
mtr -rw -c 10 lab.example.internal

Each of these tools is active in different ways. ARP is limited to the local segment. fping and Nmap send probes. MTR sends ICMP or TCP/UDP probes depending on options. Read each tool page before using it on a production network.

What "success" looks like

After installation, --check should print + for the groups you installed. A non-zero exit with a - means a command is still missing; the installer will also list failed packages and the log path. Fix the package issue, then re-run the installer or use --force if the command exists but you want a reinstall.
