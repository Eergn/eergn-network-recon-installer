This tool sends traffic to the systems you point it at. Use it only on infrastructure you own or have explicit written permission to test. The examples use private documentation ranges and placeholder names.

Overview

fping is a command-line ICMP echo tool designed to probe many hosts quickly. Unlike the traditional ping, it can take a list or generated range, send probes to multiple targets in parallel, and produce output that is easy to feed into scripts.

The installer's fping group installs the package and checks for the fping command. It is a good complement to ARP discovery: ARP sees the local link, while fping can test routed addresses that permit ICMP.

What it does

  • Probe one or many IPv4 or IPv6 targets with ICMP echo requests.
  • Generate target lists from CIDR, start/end addresses or a file.
  • Print only alive or only unreachable hosts.
  • Run count-based or continuous loop measurements.
  • Report per-target statistics, timestamps and elapsed times.

Good for

  • A quick reachability check across a documented lab range.
  • Filtering a host list before a more expensive scan.
  • Continuous reachability monitoring during a lab change.
  • Producing simple alive/dead lists for scripts.

Limits

  • ICMP is often filtered; a host can be up and still fail every probe.
  • It says nothing about open ports or services.
  • Large generated ranges can be noisy and slow on constrained links.
  • Privilege requirements depend on how the package was built and installed.
  • Round-trip time is not a reliable measure of application performance.

How the installer handles it

The fping group installs the distribution package and checks for the fping command. The installer does not modify capabilities or setuid permissions; the package decides how ICMP access is granted.

On the audited Ubuntu system, /usr/bin/fping carried cap_net_raw=ep, allowing ICMP without a root shell. Other platforms may behave differently.

Install just this group

sudo eergn-recon-installer --tool fping

From a downloaded standalone script, use sudo ./eergn-recon-installer.sh --tool fping. To install every group without the menu, use sudo eergn-recon-installer --all.

Installation

Install the group

Installs fping and verifies the command. Use sudo only if the packaged binary requires it.

sudo eergn-recon-installer --tool fping

Verify

fping -v
command -v fping
eergn-recon-installer --check
Verification is not a functional test

A version banner only proves the binary is on PATH. Run the smallest safe command against a lab endpoint to confirm the tool works in your environment.

Basic usage

Probe a CIDR range

-a prints only alive hosts; -g generates the range. Redirecting stderr hides the per-target unreachable messages.

fping -a -g 192.168.1.0/24 2>/dev/null

Probe a host list from a file

One host or address per line. Blank lines and comments may not be ignored; keep the file clean.

fping -a -f targets.txt 2>/dev/null

Collect per-host statistics

Sends five probes per target and prints a summary instead of per-packet lines.

fping -c 5 -q -s 192.168.1.10 192.168.1.20

Examples for an authorized lab

Alive list for a subnet

Create a clean list of responding addresses for later review.

fping -a -g 192.168.1.0/24 2>/dev/null | sort -V > alive.txt
wc -l alive.txt

The absence of an address from this list does not prove it is offline.

Check reachability from a file

Use a pre-approved target list rather than a whole subnet.

fping -a -f approved-hosts.txt 2>/dev/null

This is safer for production-adjacent ranges than generating a broad CIDR.

Measure loss over time

Send repeated probes and keep the summary for the record.

fping -c 10 -q -s -D 192.168.1.1

ICMP may be rate-limited by the target; interpret loss together with MTR or application tests.

Understanding the output

With -a, fping prints responding addresses. The exact lines depend on the flags.

192.168.1.1
192.168.1.10
192.168.1.20
  • Only responding targets are printed with -a.
  • Use -D or -e when timing matters.
  • Use -s for a summary of sent, received and lost probes.
  • A non-zero exit status can indicate that some targets were unreachable; check it in scripts.

Advanced usage

For continuous lab monitoring, -l and -Q can produce periodic summaries, but long-running probes should be deliberate and time-boxed. For IPv6, use -6 with an address that has a route. For scripted checks, prefer a small approved target file over broad range generation, and always capture both stdout and the exit status.

Troubleshooting

SymptomLikely causeWhat to try
All probes failICMP is blocked, the source lacks privilege or the range is routed incorrectly.Try a known responder, check ip route, and compare with ARP or Nmap host discovery.
fping: command not foundThe group is not installed or the binary is outside PATH.Rerun the group, then inspect command -v fping.
Permission deniedThe packaged binary lacks raw-socket capability and is not setuid.Run it with sudo or follow local policy for granting capabilities.
Too many targets or too much loadA large generated range is being probed at high rate.Reduce the range, use -i or -p to slow probes, and prefer a target file.

Security and etiquette

  • Probe only approved addresses; broad CIDR generation is easy to overreach.
  • ICMP sweeps are visible to network monitoring and may trigger alarms.
  • Do not use high rates on shared or production networks.
  • Treat alive lists as sensitive topology information.
  • Coordinate continuous monitoring with the network owner.
