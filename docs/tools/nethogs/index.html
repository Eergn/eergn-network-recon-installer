nethogs

Per-process network bandwidth on Linux, grouping live traffic by the program responsible rather than by host pair.

This tool sends traffic to the systems you point it at. Use it only on infrastructure you own or have explicit written permission to test. The examples use private documentation ranges and placeholder names.

Overview

nethogs is a small Linux utility that shows network bandwidth grouped by process. Where iftop answers “which peers are exchanging traffic,” nethogs answers “which local program is responsible.” It captures packets and associates them with processes using the kernel's connection information.

The installer's bandwidth group installs iftop and nethogs and checks for both commands. nethogs is Linux-focused; the installer still maps the package on macOS, but the tool is not expected to work there.

What it does

  • Display live send and receive bandwidth per process.
  • Support interactive and text/trace modes.
  • Switch between total data and throughput views.
  • Sort by sent or received traffic.
  • Filter by pcap expression and monitor selected interfaces.
  • Show full command lines or short program names.

Good for

  • Finding which local process is consuming bandwidth.
  • Confirming that a test client or server is responsible for traffic.
  • Watching a lab host during a controlled transfer.
  • Capturing a short per-process snapshot for an incident note.

Limits

  • Linux only; do not expect it to work on macOS or BSD.
  • It captures packets, so it usually needs root or a capture capability.
  • Process attribution can be incomplete for very short-lived connections.
  • It does not show remote flow detail as clearly as iftop.
  • Encrypted traffic still reveals volume, not application content.

How the installer handles it

The bandwidth group installs iftop and nethogs and checks for both commands. On the RHEL family, the installer warns that EPEL may be required. On the audited Ubuntu system, nethogs was installed as /usr/sbin/nethogs.

The installer's bandwidth group is considered complete only when these commands exist: iftop, nethogs.

Installation

Install the bandwidth group

Installs iftop and nethogs. The group is complete only when both commands exist.

sudo eergn-recon-installer --tool bandwidth

Verify

nethogs -V
nethogs -h | head
eergn-recon-installer --check
Verification is not a functional test

A version banner only proves the binary is on PATH. Run the smallest safe command against a lab endpoint to confirm the tool works in your environment.

Basic usage

Watch all active interfaces

The default view monitors interfaces that are up, excluding loopback.

sudo nethogs

Watch one interface

Focus on the lab interface to reduce noise.

sudo nethogs eth0

Take a short text snapshot

Trace mode with five refresh cycles is easier to save than the interactive view.

sudo nethogs -t -c 5 eth0

Command reference

These are the options most useful for the workflows in this documentation. Run nethogs -h for the complete list supported by your installed version.

Examples for an authorized lab

Find the busiest process

Watch the lab interface and sort by sent traffic.

sudo nethogs -d 2 -s eth0

Press q to quit. Process names may be truncated in the narrow view.

Capture five refreshes

Save a short text snapshot for a test record.

sudo nethogs -t -c 5 -d 2 eth0 > nethogs-eth0.txt

Trace mode is plain text but still depends on a live capture.

Show full command lines

Distinguish several instances of the same program.

sudo nethogs -l eth0

Command lines can contain sensitive arguments; protect the output.

Understanding the output

The interactive view groups traffic by process. Trace mode prints periodic blocks. The values below are illustrative.

Refreshing:
PID     USER    PROGRAM                            DEV        SENT      RECEIVED
1234    lab     /usr/bin/curl                       eth0       1.420 KB/s  8.900 KB/s
5678    lab     /usr/bin/ssh                        eth0       0.320 KB/s  0.410 KB/s
?       root    unknown TCP                         eth0       0.010 KB/s  0.020 KB/s
  • The PID and program name identify the local process responsible for the traffic.
  • SENT and RECEIVED are rates in the selected view mode.
  • Unknown TCP rows often represent connections that closed before attribution or kernel threads.
  • Use -v or the interactive mode keys to switch between rate and total views.

Advanced usage

Use -P to focus on one PID, or -f with a narrow pcap expression to reduce noise. For longer captures, prefer trace mode with a fixed refresh count, because the interactive display has no history. Attribution is based on the kernel's view of sockets; very short connections and some container or namespace setups may not map cleanly to a process.

Troubleshooting

SymptomLikely causeWhat to try
nethogs: command not foundIt is installed in /usr/sbin or the group is incomplete.Use sudo /usr/sbin/nethogs or check the group with --check.
Permission deniedPacket capture requires privilege.Run with sudo or grant the appropriate capture capability according to local policy.
No processes appearWrong interface, no traffic, or traffic in another network namespace.Check the interface and run a known transfer; inspect namespaces if relevant.
Many unknown TCP rowsShort-lived connections or traffic the tool cannot attribute.Use iftop for flow detail and repeat the capture during a longer transfer.
Does not work on macOSnethogs is Linux-specific.Use iftop or another platform-appropriate tool.

Security and etiquette

  • Capture only on interfaces and hosts you are authorized to monitor.
  • Command lines and process names can be sensitive; protect snapshots.
  • Do not capture credentials or personal data.
  • Promiscuous mode is not recommended; avoid it unless explicitly required.
  • Stop captures when the test ends and remove temporary files.
