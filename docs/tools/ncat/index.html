Ncat

This tool sends traffic to the systems you point it at. Use it only on infrastructure you own or have explicit written permission to test. The examples use private documentation ranges and placeholder names.

Overview

Ncat is a general-purpose network connector and listener maintained by the Nmap project. It reads and writes data across TCP, UDP, SCTP and Unix sockets, and adds features that traditional Netcat implementations lack: TLS, proxy support, connection limits, access control and connection brokering.

Ncat is part of the installer's nmap group. It is useful for confirming that a port accepts a connection, building a temporary lab listener, and moving small amounts of data between systems you control.

What it does

  • Open outbound TCP, UDP or SCTP connections and bridge them to standard input and output.
  • Listen for inbound connections, optionally accepting multiple clients.
  • Wrap a connection in TLS, with certificate and hostname verification options.
  • Proxy connections through HTTP, SOCKS4 or SOCKS5 proxies.
  • Restrict listeners by source address, connection count and idle timeout.
  • Optionally execute a command for a connection, which is powerful and dangerous.

Good for

  • Checking whether a lab port accepts a TCP connection.
  • Creating a short-lived listener for a controlled test.
  • Testing TLS by hand when a browser or client library is inconvenient.
  • Moving a small file between two lab hosts over an encrypted channel.

Limits

  • It is a transport tool, not a service scanner; it does not enumerate ports by itself.
  • The default connection is plaintext. Use --ssl when confidentiality matters.
  • -e and -c can expose a shell. They should not be used casually or on untrusted networks.
  • Option availability and behavior vary slightly between Ncat versions and distributions.
  • A successful TCP connection does not prove that the application protocol works.

How the installer handles it

Ncat has no separate installer group. It is required by the nmap group, and the group check fails if ncat is absent.

On the audited Ubuntu 26.04 system, the apt mapping installed nmap but not ncat; ncat was available as a separate package. Fedora-family and Alpine mappings request nmap-ncat. If your distribution splits the tools, install the Ncat package explicitly.

The installer's nmap group is considered complete only when these commands exist: nmap, ncat.

Install just this group

sudo eergn-recon-installer --tool nmap

From a downloaded standalone script, use sudo ./eergn-recon-installer.sh --tool nmap. To install every group without the menu, use sudo eergn-recon-installer --all.

Installation

Install the Nmap group

This is the only group that pulls in Ncat. The installer then checks for both commands.

sudo eergn-recon-installer --tool nmap

Install Ncat directly if the group check fails

Debian/Ubuntu example. Use the equivalent package for your distribution if it splits Ncat from Nmap.

sudo apt install ncat

Verify

ncat --version
command -v ncat
eergn-recon-installer --check
Verification is not a functional test

A version banner only proves the binary is on PATH. Run the smallest safe command against a lab endpoint to confirm the tool works in your environment.

Basic usage

Check a TCP port

Zero-I/O mode reports whether the connection succeeds. Add -w 3 to bound the wait.

ncat -zv 192.168.1.10 22

Open a temporary listener

Listens on all interfaces by default. Bind to a lab address with -s or restrict access with --allow.

ncat -l 8080

Accept multiple clients in a lab

Keep-open mode is convenient but should be time-limited and bound to a controlled address.

ncat -lk 127.0.0.1 8080

Examples for an authorized lab

Port check with a timeout

Confirm that a lab service accepts TCP connections without sending application data.

ncat -zv -w 3 192.168.1.10 443

A timeout or refusal is evidence about reachability, not proof that the service is healthy.

Local TLS handshake

Use Ncat as a TLS client when you only need to confirm that a handshake completes.

ncat --ssl --ssl-verify lab.example.internal 443 < /dev/null

Certificate verification requires a trust store that knows the issuing CA. For detailed certificate inspection use OpenSSL.

Restricted temporary listener

Bind a listener to loopback and allow only the local host.

ncat -l -k --allow 127.0.0.1 -s 127.0.0.1 9000

Stop the listener when the test ends. Do not expose it beyond the lab.

Understanding the output

Zero-I/O mode prints a short connection result. Exact wording differs between versions.

Ncat: Version 7.98 ( https://nmap.org/ncat )
Ncat: Connected to 192.168.1.10:22.
Ncat: 0 bytes sent, 0 bytes received in 0.01 seconds.
  • Connected means the TCP handshake completed.
  • A refusal usually means the host is reachable but nothing is listening on that port.
  • A timeout can mean filtering, routing problems or a host that is down.
  • Ncat does not identify the service; use Nmap version detection or the application's own client for that.

Advanced usage

Ncat can broker connections and host a simple chat server (--broker, --chat). These modes are useful in isolated exercises but should not be exposed to untrusted networks. TLS listeners need a certificate and key; keep private keys out of shared lab directories.

The -e and -c options turn a listener into a remote command service. Even with --allow, this is a high-risk pattern. Prefer SSH or a purpose-built service for remote administration.

Troubleshooting

SymptomLikely causeWhat to try
ncat: command not foundNcat is packaged separately from Nmap on this distribution.Install the Ncat package, then rerun eergn-recon-installer --check.
Connection refusedThe host is reachable but no process is listening on that port.Confirm the port and service state on the target; refusal is not usually a firewall drop.
Connection times outA firewall is dropping packets, the route is wrong, or the host is down.Check routing and scope, and compare with a host-discovery result.
TLS verification failsThe certificate is self-signed, expired, for another name, or the CA is not trusted.Inspect the chain with OpenSSL; do not disable verification just to make the test pass.
Listener is reachable from unexpected hostsIt bound to all interfaces without access control.Bind to a specific address and use --allow; stop the listener after the test.

Security and etiquette

  • Avoid -e and -c unless the exercise explicitly requires them.
  • Bind listeners to loopback or a lab address, not every interface.
  • Use TLS and certificate verification when data crosses an untrusted segment.
  • Stop temporary listeners and remove any files they created.
  • Do not use Ncat to bypass authentication or access controls.
