This tool sends traffic to the systems you point it at. Use it only on infrastructure you own or have explicit written permission to test. The examples use private documentation ranges and placeholder names.

Overview

Netcat is the long-standing "TCP/IP Swiss Army knife": a small utility that connects standard input and output to a network socket. It can act as a client, a listener, a quick port checker and a data-transfer helper.

The installer's netcat group installs netcat-openbsd on Debian/Ubuntu and the distribution's equivalent elsewhere, then checks for the command nc. Implementations differ: OpenBSD netcat, GNU netcat and Nmap's Ncat do not all support the same flags.

What it does

  • Open outbound TCP or UDP connections.
  • Listen on a local port for inbound connections.
  • Check whether a TCP port accepts a connection.
  • Pipe files or command output over a network connection.
  • Support IPv4 and IPv6, source-address binding and timeouts.

Good for

  • A minimal check that a port is reachable and accepting connections.
  • A quick temporary listener in an isolated lab.
  • A fallback when Ncat is unavailable.
  • Simple line-oriented data exchange for protocol experiments.

Limits

  • Plaintext only; it has no built-in TLS.
  • No authentication or access control in the basic tool.
  • Flags differ between implementations. Scripts written for one nc may fail on another.
  • The audited Debian/Ubuntu OpenBSD netcat help did not list -e; do not assume command execution support.
  • It does not identify services or enumerate ports.

How the installer handles it

The netcat group checks only for the command nc. Debian/Ubuntu gets netcat-openbsd; Fedora-family systems get nmap-ncat. On systems where Ncat is installed, nc may be provided by an alternatives link or by the Ncat package.

The installer does not replace the system default nc alternative. If multiple Netcat implementations are installed, check readlink -f "$(command -v nc)" before relying on a particular flag set.

The installer's netcat group is considered complete only when these commands exist: nc.

Install just this group

sudo eergn-recon-installer --tool netcat

From a downloaded standalone script, use sudo ./eergn-recon-installer.sh --tool netcat. To install every group without the menu, use sudo eergn-recon-installer --all.

Installation

Install the group

Installs the distribution's Netcat package and verifies nc.

sudo eergn-recon-installer --tool netcat

Verify

nc -h
readlink -f "$(command -v nc)"
eergn-recon-installer --check
Verification is not a functional test

A version banner only proves the binary is on PATH. Run the smallest safe command against a lab endpoint to confirm the tool works in your environment.

Basic usage

Check a TCP port

Zero-I/O mode with a timeout. The exact output varies by implementation.

nc -zv -w 3 192.168.1.10 22

Listen on a high port

Listens for one connection. Use -k only if your implementation supports it and the test needs multiple connections.

nc -l 8080

Send a line to a lab service

Sends bytes exactly as written. Use this only against a service you control.

printf 'HELLO' | nc -w 3 192.168.1.10 9000

These are the options most useful for the workflows in this documentation. Run nc -h for the complete list supported by your installed version.

Examples for an authorized lab

Check several lab ports

Loop over a short list and record which ports accept connections.

for port in 22 80 443 8080; do
  if nc -z -w 2 192.168.1.10 "$port"; then
    echo "open: $port"
  else
    echo "closed or filtered: $port"
  fi
done

This distinguishes success from non-success, not open from filtered. Use Nmap when that distinction matters.

Bind a listener to loopback

Keep a temporary listener off the network.

nc -l -s 127.0.0.1 -p 9000

Source and port flags vary by implementation; check nc -h on your system.

IPv6 check

Force IPv6 when a hostname resolves to both families.

nc -6 -zv -w 3 lab.example.internal 443

Use a hostname that actually has an AAAA record.

Understanding the output

OpenBSD netcat prints a short success or failure line. Wording varies between implementations and versions.

Connection to 192.168.1.10 22 port [tcp/ssh] succeeded!
  • Success means the TCP handshake completed.
  • No output with a non-zero exit status often means refusal or timeout; check the shell status.
  • Netcat does not tell you which application is listening.
  • Use -w in scripts so a filtered port cannot hang the loop.

Advanced usage

OpenBSD netcat supports proxy connections with -X and -x, source routing options and Unix-domain sockets on some builds. These are implementation-specific and not portable across every nc. For TLS, use Ncat or OpenSSL rather than trying to bolt encryption onto plain Netcat.

Troubleshooting

SymptomLikely causeWhat to try
nc: invalid option -- 'z'A different Netcat implementation is selected.Inspect readlink -f "$(command -v nc)" and use the flags documented by that version.
A port check hangsNo timeout was set and the packets are being dropped.Add -w 2 or use Nmap with a host timeout.
Listener refuses connectionsIt is bound to the wrong address, or a firewall blocks the port.Check the bind address, local firewall and whether the listener is still running.
-e is unavailableThe OpenBSD implementation does not provide remote command execution.Do not work around this; use SSH for administration.

Security and etiquette

  • Netcat is unencrypted and unauthenticated by default.
  • Do not use it to move credentials or sensitive data over untrusted links.
  • Bind listeners to loopback or a specific lab address.
  • Prefer Ncat when you need TLS or access control.
  • Remove temporary listeners and test files when finished.
