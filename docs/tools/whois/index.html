whois

This tool sends traffic to the systems you point it at. Use it only on infrastructure you own or have explicit written permission to test. The examples use private documentation ranges and placeholder names.

Overview

whois queries the registration data published by domain registries, registrars and regional internet registries. For a domain it usually returns registrar, status, name servers and dates; for an IP address it can return the allocated network and abuse contact.

The installer groups whois with dig under the dns group and checks for both commands. WHOIS is not DNS: it is a separate text protocol, and the available fields depend on the registry and on privacy redaction.

What it does

  • Query domain registration records through the appropriate registry or registrar.
  • Query IP address and autonomous-system allocation records.
  • Follow referrals from IANA or a registry to another server.
  • Choose a specific WHOIS server or port.
  • Reduce output with brief mode or hide legal disclaimers.

Good for

  • Finding the registrar and name servers for a domain.
  • Identifying the allocated network or abuse contact for an address.
  • Checking registration and expiry dates.
  • Confirming which registry is authoritative for a resource.

Limits

  • Many registries redact personal data for privacy.
  • The protocol is not standardized; output formats differ by server.
  • Rate limits and query quotas are common.
  • Registration data can be stale or incomplete.
  • It does not resolve names or test services.

How the installer handles it

The dns group installs whois along with the DNS client package and checks for both dig and whois. On the audited Ubuntu 26.04 system, the installed client was version 5.6.6.

The installer's dns group is considered complete only when these commands exist: dig, whois.

Install just this group

sudo eergn-recon-installer --tool dns

From a downloaded standalone script, use sudo ./eergn-recon-installer.sh --tool dns. To install every group without the menu, use sudo eergn-recon-installer --all.

Installation

Install the DNS group

Installs whois and the DNS client package, then checks both commands.

sudo eergn-recon-installer --tool dns

Verify

whois --version
dig -v
eergn-recon-installer --check
Verification is not a functional test

A version banner only proves the binary is on PATH. Run the smallest safe command against a lab endpoint to confirm the tool works in your environment.

Basic usage

Look up a domain

The client chooses a registry or registrar server based on its built-in configuration and follows referrals.

whois example.com

Query IANA and follow referrals

Starts at whois.iana.org and follows the referral chain. Useful when the local client chooses an unexpected server.

whois -I example.com

Look up an IP allocation

Returns the regional internet registry allocation or a referral to another registry.

whois 192.0.2.10

Examples for an authorized lab

Domain registration summary

Capture the registrar, status and name servers for a domain you own.

whois example.com | grep -Ei 'registrar:|status:|name server:|creation|expiry|updated'

Field names differ by registry; the filter is illustrative.

IP allocation and abuse contact

Find the network allocation for an address in scope.

whois 192.0.2.10 | grep -Ei 'inetnum|netrange|orgname|abuse-mailbox|country'

Privacy redaction may remove contact details.

Start from IANA

Follow referrals explicitly when debugging a lookup.

whois -I -H example.com

-H hides disclaimers, which makes output easier to read but removes context.

Understanding the output

WHOIS output is plain text whose fields vary by server. The example is illustrative.

Domain Name: EXAMPLE.COM
Registry Domain ID: 0000000_DOMAIN_COM-VRSN
Registrar: Example Registrar, Inc.
Creation Date: 1995-08-14T04:00:00Z
Registry Expiry Date: 2027-08-13T04:00:00Z
Name Server: NS1.EXAMPLE.NET
Name Server: NS2.EXAMPLE.NET
Domain Status: clientTransferProhibited
  • The server and query date matter; WHOIS records change and may be cached.
  • Privacy services may replace registrant details with a proxy.
  • Name servers here are registration data, not proof of current DNS answers.
  • Some registries rate-limit repeated queries; keep lookups minimal.

Advanced usage

Use -h to query a known registry directly when the local client's referral logic picks an unexpected server. For RIPE-style databases, options such as -B, -r and -T change how much contact and object data is returned. These flags are server-specific and should not be assumed to work everywhere.

Troubleshooting

SymptomLikely causeWhat to try
whois: command not foundThe DNS group is incomplete.Install the distribution's whois package and rerun eergn-recon-installer --check.
connect: Connection refusedThe selected WHOIS server is unavailable or blocks this client.Try whois -I or a different registry server.
No match for ...The resource is not registered in that server's database.Check the spelling, try the correct registry, or use -I.
Rate-limit or quota messageThe registry limits repeated queries.Wait, reduce queries, and cache results locally.
Personal data is missingPrivacy redaction is applied by the registry or registrar.Do not attempt to bypass redaction; use published abuse contacts.

Security and etiquette

  • Do not query domains or addresses outside your authorized scope unnecessarily.
  • WHOIS queries are visible to the registry and may reveal your interest.
  • Respect rate limits and terms of service.
  • Do not attempt to reconstruct redacted personal data.
  • Treat registration and contact data as potentially sensitive.
