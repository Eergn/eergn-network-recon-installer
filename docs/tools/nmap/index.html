Nmap

This tool sends traffic to the systems you point it at. Use it only on infrastructure you own or have explicit written permission to test. The examples use private documentation ranges and placeholder names.

Overview

Nmap (Network Mapper) is a command-line scanner for discovering hosts and services on a network. It can enumerate live addresses, probe TCP and UDP ports, identify service banners and versions, make operating-system guesses, and run scripts from the Nmap Scripting Engine (NSE).

The installer groups Nmap with Ncat because the upstream Nmap project ships both. The nmap group is only considered installed when both nmap and ncat are on PATH. On several distributions Ncat is a separate package, which is covered under installer handling below.

What it does

  • Host discovery with ARP, ICMP, TCP and UDP probes, including a list-only mode.
  • TCP connect, SYN, ACK, window, null, FIN, Xmas and idle scans, plus UDP and IP-protocol scans.
  • Port selection by range, list, top-N frequency or service name.
  • Service and version detection with adjustable probe intensity.
  • Operating-system fingerprinting and traceroute-style path information.
  • NSE scripts for discovery, safe configuration checks and deeper inspection.
  • Normal, XML, grepable and script-kiddie output formats.

Good for

  • Building an inventory of live lab hosts before service-level testing.
  • Confirming which ports a firewall or security group actually exposes.
  • Identifying the product and version behind an open port.
  • Producing machine-readable XML for later comparison.

Limits

  • It is a mapper, not a full vulnerability scanner. NSE checks are narrow and version-dependent.
  • Filtered ports are ambiguous: a firewall, a rate limiter and a down service can look similar.
  • SYN, UDP and OS detection need raw sockets, so they usually need root or specific capabilities.
  • Aggressive timing and large port ranges are noisy and can disrupt fragile lab equipment.
  • OS detection is a guess based on fingerprints, not a guarantee.

How the installer handles it

The installer's nmap group installs the distribution's Nmap package and checks for both nmap and ncat. On Debian and Ubuntu, the audited installation had nmap but not ncat after installing the nmap package alone, because ncat is packaged separately in that release.

The installer's nmap group is considered complete only when these commands exist: nmap, ncat.

Install just this group

sudo eergn-recon-installer --tool nmap

From a downloaded standalone script, use sudo ./eergn-recon-installer.sh --tool nmap. To install every group without the menu, use sudo eergn-recon-installer --all.

Installation

Install the group

This installs Nmap and any package the group mapping requests. It does not grant authorization to scan anything.

sudo eergn-recon-installer --tool nmap

Verify

nmap --version
ncat --version
eergn-recon-installer --check
Verification is not a functional test

A version banner only proves the binary is on PATH. Run the smallest safe command against a lab endpoint to confirm the tool works in your environment.

Basic usage

Discover hosts without scanning ports

Sends host-discovery probes only. The result is a list of addresses that responded, not a port inventory.

nmap -sn 192.168.1.0/24

Scan common TCP ports with version detection

Uses a TCP connect scan when run without privileges. Version detection adds probes and time.

nmap -sV --top-ports 100 192.168.1.10

Use a SYN scan with an explicit port list

A SYN scan is faster and less likely to appear in application logs, but it needs raw sockets and is still visible to network monitoring.

sudo nmap -sS -p 22,80,443,8080 192.168.1.10

Command reference

These are the options most useful for the workflows in this documentation. Run nmap --help for the complete list supported by your installed version.

Examples for an authorized lab

Inventory a lab subnet

Combine a fast host-discovery pass with a small port set, then expand only on hosts that matter.

sudo nmap -sn -n 192.168.1.0/24 -oA lab-hosts
sudo nmap -sV --top-ports 100 -iL lab-hosts.gnmap -oA lab-top100

The second command accepts the grepable output as input, but it will include only lines Nmap can parse as hosts. Review the file first.

Check a web host without scripts

Start with explicit ports and light version detection before adding NSE.

nmap -sV -p 80,443,8080,8443 --version-light 192.168.1.20

Version detection can trigger application logs and web application firewalls.

Use only safe NSE discovery

Restrict scripts to a non-intrusive category and keep timing conservative.

nmap -sV -Pn -p 22,80,443 --script "safe and discovery" --max-rate 200 192.168.1.20

Script categories are not a guarantee of safety on fragile or production systems. Test in the lab first.

Understanding the output

A version scan prints a report per host. The values below are illustrative; your ports, services and timings will differ.

Starting Nmap 7.98 ( https://nmap.org )
Nmap scan report for lab-gateway (192.168.1.1)
Host is up (0.0021s latency).
Not shown: 998 closed tcp ports (reset)
PORT    STATE SERVICE  VERSION
22/tcp  open  ssh      OpenSSH 9.6 (protocol 2.0)
80/tcp  open  http     nginx 1.24.0
443/tcp open  ssl/http nginx 1.24.0

Service detection performed. Please report any incorrect results.
Nmap done: 1 IP address (1 host up) scanned in 6.42 seconds
  • STATE distinguishes open, closed and filtered ports. Filtered means Nmap could not tell whether the port is open.
  • VERSION is a fingerprint guess. Treat it as a starting point, not proof of patch level.
  • The Not shown line summarizes ports that did not respond as open; it is not a complete list of every port.
  • Use -oA when you need to compare runs or feed results into another tool.

Advanced usage

NSE is powerful and easy to overuse. Start with --script-help <name>, prefer the safe and discovery categories, and record the exact script set with your results. Avoid running --script vuln or brute-force categories against systems outside an isolated lab.

For reproducible inventories, disable name resolution with -n, export XML with -oX, and keep the command line in a run log. XML includes timing and status details that normal output omits.

Troubleshooting

SymptomLikely causeWhat to try
ncat is missing after installDebian/Ubuntu package Ncat separately; the installer's apt mapping requests only nmap.Install sudo apt install ncat, then rerun eergn-recon-installer --check.
You requested a scan type which requires root privilegesSYN, UDP, OS detection or raw packet options need elevated privileges.Use sudo for that single scan, or switch to -sT for a connect scan.
Every port is filteredA host or network firewall is dropping probes, or the target is on a different path.Confirm scope and routing, try a known-open port, and avoid assuming the service is down.
The scan is very slowVersion detection, UDP, many ports or conservative timing.Reduce the port set, raise --max-rate cautiously, or use -T3 and --version-light.
Host appears downICMP is filtered and host discovery is too strict.Try -Pn on an address you know is in scope, then verify the result with another tool.

Security and etiquette

  • Scan only addresses and ports inside the written scope.
  • Prefer the smallest scan that answers the question; avoid full-range scans by habit.
  • Use rate limits on shared, wireless or production-adjacent networks.
  • Do not run intrusive or brute-force NSE categories outside an isolated lab.
  • Run as root only for the scan that needs it, not for an entire shell session.
  • Treat scan output as sensitive: it maps exposed services and may reveal internal names.
