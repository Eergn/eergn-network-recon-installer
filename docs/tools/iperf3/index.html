This tool sends traffic to the systems you point it at. Use it only on infrastructure you own or have explicit written permission to test. The examples use private documentation ranges and placeholder names.

Overview

iperf3 measures achievable throughput between two endpoints. One side runs a server, the other a client; the client sends or receives a stream and both report bitrate, retransmissions and other counters. It is a controlled link and host performance test, not an internet speed test.

The installer's iperf3 group installs the distribution package and checks for the iperf3 command. Throughput tests require a server you control on the other end and a port that is allowed through every firewall on the path.

What it does

  • Measure TCP throughput in either direction.
  • Send UDP streams at a specified bitrate and report loss and jitter.
  • Run multiple parallel streams.
  • Use a fixed duration, byte count or block count.
  • Produce JSON for automated comparison.

Good for

  • Verifying that a lab link meets an expected throughput target.
  • Comparing TCP and UDP behavior across a WAN or overlay.
  • Checking the effect of parallel streams on a path.
  • Producing repeatable before/after measurements.

Limits

  • It measures the path and the two hosts, not just the network.
  • CPU, disk, virtual NICs and offload can limit results.
  • A single TCP stream may not fill a high-bandwidth, high-latency path.
  • UDP results depend heavily on the configured bitrate.
  • Internet speed tests and iperf3 answer different questions.

How the installer handles it

The iperf3 group installs the distribution package and checks for iperf3. The openSUSE mapping requests the package named iperf; the group still checks for the iperf3 command, so verify the command after installation.

The installer's iperf3 group is considered complete only when these commands exist: iperf3.

Install just this group

sudo eergn-recon-installer --tool iperf3

From a downloaded standalone script, use sudo ./eergn-recon-installer.sh --tool iperf3. To install every group without the menu, use sudo eergn-recon-installer --all.

Installation

Install the group

Installs iperf3 and verifies the command.

sudo eergn-recon-installer --tool iperf3

Verify

iperf3 --version
command -v iperf3
eergn-recon-installer --check
Verification is not a functional test

A version banner only proves the binary is on PATH. Run the smallest safe command against a lab endpoint to confirm the tool works in your environment.

Basic usage

Start a server

Runs on TCP port 5201 by default. Use -1 to handle a single test and exit, or -D to daemonize.

iperf3 -s

Run a ten-second TCP test

The client sends to the server. Add -R to reverse the direction.

iperf3 -c 192.168.1.20 -t 10

Run UDP at a target bitrate

UDP reports loss and jitter. Without -b, the default UDP rate is low.

iperf3 -c 192.168.1.20 -u -b 100M -t 10

Examples for an authorized lab

One-off server for a controlled test

Run a server that accepts one client and then exits.

iperf3 -s -1 -p 5201

Coordinate the time window with the client side and close the port when finished.

Ten-second TCP test in both directions

Measure send and receive separately rather than assuming symmetry.

iperf3 -c 192.168.1.20 -t 10
iperf3 -c 192.168.1.20 -t 10 -R

Keep the duration and stream count constant when comparing results.

Four parallel streams with JSON

Check whether a single stream is the bottleneck.

iperf3 -c 192.168.1.20 -t 15 -P 4 -J > iperf3-p4.json

More streams can raise aggregate throughput but also CPU load on both ends.

Understanding the output

The client prints interval lines and a summary. The values below are illustrative.

[ ID] Interval           Transfer     Bitrate         Retr
[  5]   0.00-10.00  sec  1.10 GBytes   944 Mbits/sec    0   sender
[  5]   0.00-10.00  sec  1.10 GBytes   943 Mbits/sec        receiver

iperf Done.
  • Bitrate is the measured throughput for the interval or summary.
  • Retr counts TCP retransmissions; a high count can indicate loss or congestion.
  • Compare sender and receiver values; a large gap can indicate loss or a bottleneck.
  • For UDP, read loss, jitter and the configured target rate, not just bitrate.

Advanced usage

Use -P to test whether one stream is limited by CPU or window size, -R to separate direction-specific behavior, and -J to keep structured results. Set a fixed duration and note the MTU, interface and offload settings. On virtualized hosts, check whether the hypervisor or virtual switch is the limiting factor before blaming the physical link.

Troubleshooting

SymptomLikely causeWhat to try
Connection refusedNo server is listening on that host and port.Start iperf3 -s on the server and confirm the port.
No route to hostRouting or firewall problem between client and server.Check the route and whether TCP 5201 (or the chosen port) is allowed.
Throughput is much lower than expectedCPU, disk, virtual NIC, offload, a single stream or congestion.Try parallel streams, a different direction, and check host load.
UDP shows heavy lossThe target bitrate exceeds the path capacity or the receiver cannot keep up.Lower -b until loss is acceptable, then increase gradually.
openSUSE install did not provide iperf3The mapping requests a package named iperf.Verify iperf3 --version; install the iperf3 package if the command is missing.

Security and etiquette

  • Run the server only for the test window and restrict it with a firewall.
  • Do not expose an iperf3 server to the public internet.
  • Use only endpoints and paths in scope.
  • High-bitrate tests can consume capacity and affect other users.
  • Treat throughput results as sensitive performance data.
