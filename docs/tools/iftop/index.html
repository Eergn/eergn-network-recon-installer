iftop

Real-time bandwidth by host pair and flow, with sorting, filters and a text mode suitable for short captures.

This tool sends traffic to the systems you point it at. Use it only on infrastructure you own or have explicit written permission to test. The examples use private documentation ranges and placeholder names.

Overview

iftop shows live bandwidth usage on an interface, grouped by host pair. It is a packet-capture viewer, so it sees traffic on the local interface and can show which peers are exchanging data, how much, and in which direction.

The installer's bandwidth group installs iftop and nethogs and checks for both commands. Use iftop for flow-level visibility and nethogs for process-level attribution.

What it does

  • Display live inbound and outbound bandwidth by host pair.
  • Filter traffic with a pcap expression.
  • Sort by recent, short-term or long-term averages.
  • Show ports and service names.
  • Produce a text-mode snapshot for logs or short captures.

Good for

  • Seeing which peers are consuming bandwidth on a lab interface.
  • Confirming that a test stream is flowing in the expected direction.
  • Filtering one port or subnet during a focused test.
  • Capturing a short text snapshot when a full TUI is impractical.

Limits

  • It shows flows by address, not processes; use nethogs for processes.
  • It sees only traffic visible on the selected interface.
  • Promiscuous mode may be restricted by the environment.
  • It does not retain history; save text output if you need a record.
  • Encrypted or switched traffic may not reveal application meaning.

How the installer handles it

The bandwidth group installs iftop and nethogs and checks for both commands. Packet capture usually requires root or a capture capability; the installer does not grant that privilege.

On the audited Ubuntu system, iftop was installed as /usr/sbin/iftop, which is not always on a non-root user's PATH. Calling it with an absolute path or sudo resolves that.

The installer's bandwidth group is considered complete only when these commands exist: iftop, nethogs.

Install just this group

sudo eergn-recon-installer --tool bandwidth

From a downloaded standalone script, use sudo ./eergn-recon-installer.sh --tool bandwidth. To install every group without the menu, use sudo eergn-recon-installer --all.

Installation

Install the bandwidth group

Installs iftop and nethogs. The group is complete only when both commands exist.

sudo eergn-recon-installer --tool bandwidth

Verify

iftop -h | head
nethogs -h | head
eergn-recon-installer --check
Verification is not a functional test

A version banner only proves the binary is on PATH. Run the smallest safe command against a lab endpoint to confirm the tool works in your environment.

Basic usage

Watch an interface

Numeric addresses, numeric ports and port display. Replace eth0 with the lab interface.

sudo iftop -i eth0 -n -N -P

Capture a short text snapshot

Text mode prints a snapshot and exits after ten seconds. Useful for logs.

sudo iftop -t -s 10 -n -N -i eth0

Filter one port

The filter uses pcap syntax. Keep expressions narrow and quote them.

sudo iftop -i eth0 -f 'port 443'

Examples for an authorized lab

Watch one lab interface

Keep names numeric and show ports for a focused view.

sudo iftop -i eth0 -n -N -P

Press q to quit. The display is live and does not persist.

Capture a ten-second text snapshot

Save a short record of the busiest flows.

sudo iftop -t -s 10 -n -N -i eth0 > iftop-eth0.txt

Text mode is a snapshot, not a packet capture. It does not preserve per-packet detail.

Filter to HTTPS

Reduce noise while checking a web test.

sudo iftop -i eth0 -f 'tcp port 443' -n -N

The filter applies to captured packets; it does not decrypt traffic.

Show a specific subnet

Focus on traffic in or out of the lab network.

sudo iftop -i eth0 -F 192.168.1.0/24 -n -N

Use the network that matches the interface and the authorized scope.

  • The three rate columns are short-term, medium-term and long-term averages.
  • Arrows show direction between the two peers; => and <= indicate the dominant direction.
  • TX, RX and TOTAL summarize the interface during the capture.
  • Use -B if you need bytes rather than bits, and record the unit in your notes.

Advanced usage

iftop's display is intentionally ephemeral. For long-running visibility, use the text mode with a time limit and save the result, or use a flow exporter if the environment provides one. Promiscuous mode can reveal other hosts' traffic on a shared segment, which raises both technical and privacy concerns; use it only with explicit authorization. If you need to attribute traffic to a process, use nethogs on the same interface.

Troubleshooting

SymptomLikely causeWhat to try
iftop: command not foundIt is installed in /usr/sbin or the group is incomplete.Use sudo /usr/sbin/iftop or check the group with --check.
Permission deniedPacket capture requires privilege.Run with sudo or grant the appropriate capture capability according to local policy.
No traffic appearsWrong interface, no matching traffic, or a filter that excludes it.Check the interface and remove the filter; compare with ip -s link.
Promiscuous mode failsThe environment restricts promiscuous capture.Run without -p; it is often unnecessary for local host traffic.
Names resolve slowlyReverse DNS is slow for many peers.Add -n to keep addresses numeric.

Security and etiquette

  • Capture only on interfaces and segments you are authorized to monitor.
  • Promiscuous mode can expose other users' traffic; use it sparingly and lawfully.
  • Do not capture credentials or personal data.
  • Store snapshots securely; they reveal internal addresses and traffic patterns.
  • Stop captures when the test ends and remove temporary files.
