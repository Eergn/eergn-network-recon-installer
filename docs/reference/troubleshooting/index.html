Troubleshooting

A general index of failure modes across the installer, APT repository and installed tools, with the evidence to collect before changing anything.

Start with evidence

eergn-recon-installer --version
eergn-recon-installer --check
cat /etc/os-release
command -v apt-get dnf yum pacman zypper apk brew
id
command -v sudo

Also locate the installer log path printed at the start of the run. The most useful error is usually the package manager's own line near the end of that log, not the installer's summary.

False alarms to avoid

  • Dry-run success is not installation. The dry run prints simulated commands and ok lines.
  • A skipped group is not necessarily broken. The installer skips groups whose commands already exist.
  • A non-zero --check can be intentional. It checks all nine groups, even if you installed three.
  • A filtered port is not closed. A firewall may be dropping probes.
  • A scanner finding is not automatically a vulnerability. Confirm the version and configuration in context.

What not to do

  • Do not disable GPG signature verification to bypass an APT error.
  • Do not recursively chmod or chown system directories.
  • Do not run every tool as root when only raw-socket operations need it.
  • Do not paste internal addresses, hostnames or certificates into a public issue.

Reporting a problem

Include the distribution and version, installer version, exact command, whether it was root or sudo, the relevant log tail, and the output of eergn-recon-installer --check. Remove secrets, internal addresses and personal data first. The repository has issue tracking, but no dedicated security policy or contact was found in the source; do not invent one.
