Installer command reference

Every option implemented by eergn-recon-installer.sh version 1.0.0, with the behavior verified from the source rather than from a generic template.

Synopsis

eergn-recon-installer [options]
eergn-recon-installer.sh [options]

The packaged command is eergn-recon-installer. The standalone script is usually named eergn-recon-installer.sh. Both run the same code.

Options

OptionArgumentBehaviorNotes
-a, --allnoneSelect every tool group and skip the menuMain mode sets the selection to all nine IDs
-t, --toolIDSelect one group; may be repeatedUnknown IDs fail with an error and point to --list
-l, --listnonePrint the nine groups and exitDoes not detect a package manager or need root
-c, --checknonePrint installed/missing commands for all groups and exitNo root needed; exit 0 only if all commands exist
-y, --yesnoneSkip the confirmation promptNon-interactive runs also skip the prompt
-n, --dry-runnonePrint package-manager commands without executing themStill prints simulated ok lines; verify separately
-f, --forcenoneReinstall even when a group's commands already existDoes not bypass package-manager errors
--no-bannernoneHide the EERGN logoUseful for provisioning logs
-v, --versionnonePrint name, version and author, then exitExits before package-manager detection
-h, --helpnoneShow help and exitShows the banner unless --no-banner is also used

Options are parsed in order. The mode flags are --all, --tool, --list and --check. Avoid combining them; the last mode flag generally determines the selected mode, with --all overriding the accumulated selection when it is the final mode. Use one mode per invocation.

Modes

InvocationWhat happens
No options, interactive terminalShows the numbered menu and asks for a choice
No options, non-interactive shellInstalls all groups
--listPrints the group table and exits
--checkPrints a status table for all groups and exits with 0 or 1
--allInstalls all nine groups
--tool IDInstalls only the selected group(s)

The interactive menu accepts space-separated numbers such as 1 3 5, a for all, or q to quit. An empty choice is treated as all. Invalid non-numeric input exits with an error.

Installation examples

# Install everything without prompts
sudo eergn-recon-installer --all -y

# Install selected groups
sudo eergn-recon-installer -t nmap -t tls

# Preview a full install
eergn-recon-installer --all --dry-run

# Audit the machine without root
eergn-recon-installer --check

# Provisioning-friendly invocation
sudo eergn-recon-installer --all -y --no-banner

# Reinstall a group whose commands are present
sudo eergn-recon-installer -t tls --force

These examples match the usage documented in the README and the options implemented in the script. The installer does not accept per-tool names such as -t dig; use the group ID dns.

Behavior details

Package index refresh

The installer runs apt-get update, zypper --non-interactive refresh or apk update before installing. It does not refresh dnf, yum, pacman or Homebrew indexes explicitly.

Privilege handling

On Homebrew it refuses to run as root. On Linux it uses sudo when not already root, and exits if neither root nor sudo is available. Package manager commands are executed with non-interactive flags where the source sets them (for example DEBIAN_FRONTEND=noninteractive for apt).

Skip and force

Before installing a group, the installer checks whether every required command exists. If so, it skips the group. --force disables that check. --dry-run also disables the skip check so you can see the commands.

Failure handling

Packages are installed one at a time. A failure records the package name, prints failed, and continues with the next package and group. At the end, failed packages are listed with a hint about EPEL on the RHEL family, plus the installer log path.

Exit status

CodeMeaning
0All selected tools were present at the end, or a non-install mode completed successfully
1At least one selected command is still missing, or an option/argument error occurred
0 from --dry-runThe dry run finished; this does not mean tools are installed
0 from --checkEvery command in all nine groups exists
1 from --checkAt least one command is missing
0 from menu quit or abortThe user chose q or answered no to confirmation

Environment variables affecting the installer

VariableEffectSource of truth
NO_COLORAny non-empty value disables ANSI colorsRead at startup
PATHUsed to find package managers, commands and toolsShell environment
TERM / TTY stateControls color and whether the menu is offeredTerminal detection via [ -t ]

There is no configuration file and no environment variable for selecting a package manager, tool group, package name or log path. The package manager is detected automatically in this order: macOS/Homebrew, apt, dnf, yum, pacman, zypper, apk. See Configuration for what is deliberately fixed.

Logging

The installer creates a temporary log at startup, normally via mktemp -t Eergn-installer.XXXXXX, with /tmp/Eergn-installer.log as a fallback. Package-manager stdout and stderr are redirected there. The path is printed at the start and again when packages fail.

Not implemented

The source has no --uninstall, --update, install profiles, JSON output, shell completions, RPM package, Homebrew formula, Docker image or --sysinfo feature. Those appear only as roadmap ideas in the README and should not be documented as available.
