Configuration

What you can configure, what is detected automatically, and what is intentionally fixed in the installer source.

There is no configuration file

Version 1.0.0 does not read a configuration file, dotfile or project-local settings file. Behavior is controlled by command-line flags and a few environment variables. The package manager, package names, tool IDs, log location and testssl.sh fallback path are defined in the script.

Runtime environment variables

VariableEffectWhen it applies
NO_COLORAny non-empty value disables ANSI colorsAny run; useful in logs and CI
PATHDetermines which package managers and tool commands are foundDetection and status checks
TERMPart of terminal capability detection; color also requires a TTYOutput styling

The installer checks [ -t 1 ] before enabling color and [ -t 0 ] before offering the interactive menu or confirmation prompt. Redirecting stdout or running under a scheduler changes those decisions.

Package manager detection order

Darwin -> Homebrew (brew must exist)
apt-get -> apt
dnf     -> dnf
yum     -> dnf package mapping
pacman  -> pacman
zypper  -> zypper
apk     -> apk
otherwise -> error: no supported package manager

There is no option or environment variable to override detection. If multiple managers exist, the order above wins. On macOS, Homebrew is mandatory; other managers are not used.

APT client configuration

This is configuration on the consuming machine, not in the installer. The recommended source line is:

deb [signed-by=/usr/share/keyrings/eergn-archive-keyring.gpg] https://eergn.github.io/eergn-network-recon-installer ./

It lives in /etc/apt/sources.list.d/eergn.list. The signed-by option binds the repository to the downloaded key. Removing the file removes the repository; removing the key without removing the source causes APT signature errors.

Maintainer-only environment variables

scripts/make-apt-repo.sh reads these when publishing the repository:

VariableDefaultPurpose
SITE_URLhttps://eergn.github.io/eergn-network-recon-installerPublic repository URL written into generated metadata/pages
KEY_NAMEEergn APT RepositoryName used to find or generate the signing key
KEY_EMAILEergn@users.noreply.github.comEmail for a generated key
KEY_FPRemptyExisting key fingerprint to sign with

These variables do not affect the installer at runtime.

Customizing the installer

There is no supported extension mechanism. To change package names, add a group or change the fallback path, edit the Bash source and rebuild the package. A safe local workflow is:

cp eergn-recon-installer.sh eergn-recon-installer.local.sh
# edit the copy
bash -n eergn-recon-installer.local.sh
./eergn-recon-installer.local.sh --list
./eergn-recon-installer.local.sh --all --dry-run

Review Contributing for the data structures that must be updated together. For local policy, prefer wrapping the installer in your own provisioning script rather than editing the upstream package, so updates remain possible.

What is not configurable

  • Tool group membership and IDs.
  • Package names per distribution.
  • The log directory or log filename pattern.
  • Confirmation behavior beyond --yes and TTY detection.
  • The testssl.sh install directory or symlink target.
  • Default timing, ports or scan options for the external tools; those belong to the tools themselves.
