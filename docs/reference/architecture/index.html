Architecture

How a single Bash script, a Debian package, a signed APT repository and a static documentation site fit together.

Repository layout

.
├── eergn-recon-installer.sh      # the installer (single source of behavior)
├── README.md                     # project overview and quick reference
├── LICENSE                       # GPL-3.0
├── scripts/
│   ├── build-deb.sh              # builds dist/eergn-recon-installer_<version>_all.deb
│   └── make-apt-repo.sh          # builds and signs the repository in docs/
├── dist/                         # ignored build output (.deb)
└── docs/                         # GitHub Pages site root and APT repository
    ├── index.html                # landing page
    ├── assets/                   # CSS, JavaScript, images
    ├── documentation/            # documentation hub and guides
    ├── installation/             # installation guide
    ├── tools/                    # catalog and 13 tool pages
    ├── reference/                # installer references
    ├── eergn-recon-installer_1.0.0_all.deb
    ├── Packages, Packages.gz
    ├── Release, Release.gpg, InRelease
    ├── eergn-archive-keyring.gpg
    ├── eergn-archive-keyring.asc
    └── .nojekyll

GitHub Pages serves the docs/ directory because the repository is configured as a project site with the /docs folder as its source. The .nojekyll file prevents Jekyll processing, which keeps files such as Packages and the keyring available as-is.

The installer script

eergn-recon-installer.sh is a self-contained Bash program. It does not source repository files at runtime. Its main sections are:

SectionResponsibility
State and constantsVERSION, ALL_IDS, mode flags, package-manager key, log path
Output helpersBanner, info/warn/error, step headings, status table
Tool definitionstool_desc, tool_cmds, pkgs_for, testssl_pkg
DetectionCommand presence, package-manager detection, privilege setup
Executionrun, index refresh, package install, testssl.sh fallback
Reportingprint_status, failed package list, final exit code
Menu and argumentsInteractive selection, confirmation, option parsing

The critical data model is the intersection of four functions:

  • ALL_IDS defines the valid group IDs and menu order.
  • tool_cmds defines the commands that must exist for a group to count as installed.
  • pkgs_for maps each group to package names per package manager.
  • tool_desc provides human-readable labels.

Adding a group means updating all four, plus any special handling such as the testssl.sh fallback. See Contributing.

Installation flow

parse arguments
  -> banner unless --no-banner
  -> list / check / all / menu / non-interactive-all
  -> detect package manager
  -> set up sudo (or refuse root on Homebrew)
  -> print package manager and log path
  -> confirm unless --yes / non-interactive
  -> refresh index where supported
  -> for each selected group:
       -> skip if all commands present and not --force/--dry-run
       -> install each mapped package one at a time
       -> ensure testssl.sh for the tls group
  -> print status table for selected groups
  -> print failed packages and log path if needed
  -> exit 0 only if every selected command is present

Package build

scripts/build-deb.sh reads VERSION="..." from the installer, stages a Debian package tree, installs the script to /usr/bin/eergn-recon-installer, and generates:

  • DEBIAN/control with package, version, architecture, dependency and homepage fields.
  • /usr/share/doc/eergn-recon-installer/README.md, copyright and a gzipped changelog.
  • A gzipped man page at /usr/share/man/man1/eergn-recon-installer.1.gz.

It requires dpkg-deb from dpkg-dev. Output goes to dist/, which is ignored by Git except for the copies under docs/.

APT repository build

scripts/make-apt-repo.sh is a maintainer tool. It:

  1. Finds or generates an Ed25519 signing key named Eergn APT Repository.
  2. Runs build-deb.sh and copies the .deb into docs/.
  3. Runs dpkg-scanpackages to produce Packages and Packages.gz.
  4. Writes a Release file with SHA-256 hashes.
  5. Creates InRelease (clearsigned) and Release.gpg.
  6. Exports the public key as eergn-archive-keyring.gpg and .asc.

The generated key defaults to no expiry and no passphrase when the script has to create one. The published key in this repository is Ed25519 with fingerprint 900D437EB8F512053DA25632AEF17B55E71A8350. Key custody and passphrase policy are operational concerns for the maintainer, not properties an APT client can verify from the key alone.

Site preservation

The APT repository script used to rewrite docs/index.html with a minimal landing page. The current script preserves an existing docs/index.html so publishing repository metadata does not destroy the documentation site. If no landing page exists, it writes a minimal fallback.

Documentation site

The site is static HTML, CSS and JavaScript. There is no build step, static-site generator or frontend framework. Key details:

  • All internal links are relative, so the site works under the GitHub Pages project subpath /eergn-network-recon-installer/.
  • assets/css/site.css contains the design system and responsive rules.
  • assets/js/site.js implements mobile navigation, the docs sidebar, copy buttons, the client-side documentation search, the table of contents and the tool catalog filter.
  • assets/js/search-index.js is the search data source; it must be updated when pages are added.
  • Documentation pages are self-contained HTML with their own header, sidebar and footer. Relative asset paths depend on directory depth.

The site does not require JavaScript to read content or follow navigation. Search, copy buttons, the mobile menu and catalog filtering are enhancements.

Versioning and metadata

The installer version appears in the script constant, the Debian control file generated at build time, the man page, the filenames in docs/, and docs/Packages. When releasing, all of these must stay consistent. The package version currently published is 1.0.0.

Known architectural limitations

  • No automated test suite or CI configuration was found in the repository.
  • The installer is not idempotent for package contents beyond the command-existence skip; it relies on the package manager.
  • The testssl.sh Git fallback clones the default branch shallowly and does not pin a commit.
  • There is no uninstall, update, profile or JSON output feature in the installer.
  • Documentation navigation is repeated in each page, so adding a page requires updating links in multiple files.
