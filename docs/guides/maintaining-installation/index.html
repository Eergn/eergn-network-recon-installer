Maintaining the installation

Keep the installer and external tools current, audit what changed, and remove components without leaving a broken repository behind.

Purpose

Maintenance is deliberately simple: use the system package manager for packages, replace the standalone script when needed, and verify with the installer's own --check. The project does not currently provide --update or --uninstall commands.

Updating the APT package

sudo apt update
sudo apt upgrade
eergn-recon-installer --version
eergn-recon-installer --check

apt upgrade upgrades installed packages with available updates. If you want to see what would change first, use sudo apt list --upgradable. The repository metadata is refreshed by apt update.

Updating external tools

# Debian-based systems
sudo apt update
sudo apt upgrade

# Fedora / RHEL family
sudo dnf upgrade

# Arch
sudo pacman -Syu

# openSUSE
sudo zypper update

# Alpine
sudo apk upgrade

# macOS (Homebrew)
brew update
brew upgrade

Package availability and versions are controlled by your distribution. The installer only installs groups and checks for command presence; it does not pin versions.

Auditing versions

nmap --version | head -n 1
nc -h 2>&1 | head -n 1
arp-scan --version
fping -v
mtr --version
dig -v
whois --version
openssl version
testssl.sh --version 2>/dev/null || testssl --version
iperf3 --version
iftop -h 2>&1 | head -n 1
nethogs -V

These commands are also a quick way to discover whether a tool has been replaced or removed after a system upgrade. Record the versions with your assessment results when output interpretation depends on them.

Updating the standalone script

The script has no self-update command. Download the newer copy, inspect the change, and replace your local file:

curl -LO https://github.com/Eergn/eergn-network-recon-installer/releases/latest/download/eergn-recon-installer.sh
chmod +x eergn-recon-installer.sh
./eergn-recon-installer.sh --version

If you installed from APT, prefer APT updates so the packaged man page and metadata stay in sync.

Removing the installer

sudo apt remove eergn-recon-installer

# Optional: remove the repository source and key
sudo rm /etc/apt/sources.list.d/eergn.list
sudo rm /usr/share/keyrings/eergn-archive-keyring.gpg
sudo apt update

Removing the package leaves the external tools installed. Remove only the tools you no longer need, using your package manager. Removing testssl.sh's Git fallback is a manual step if it was used:

# Check before removing anything
ls -ld /opt/testssl.sh /usr/local/bin/testssl.sh 2>/dev/null
# If and only if you no longer need the Git fallback:
# sudo rm -rf /opt/testssl.sh
# sudo rm /usr/local/bin/testssl.sh
Do not remove shared packages casually

Some tools may already be installed for other purposes. Review the package list before removing anything, and do not delete a shared system package just because the installer group also uses it.

Verifying after an upgrade

eergn-recon-installer --check
# Exit code 0 means every command in all nine groups is present.

On a machine where you intentionally installed only some groups, a non-zero --check is expected. Read the table rather than treating the exit code as an installation failure.

Repository health

Maintainers can verify the repository metadata after publishing:

curl -fsSL https://eergn.github.io/eergn-network-recon-installer/Release | sed -n '1,20p'
curl -fsSL https://eergn.github.io/eergn-network-recon-installer/Packages | sed -n '1,25p'

The Release file lists the SHA-256 hashes of Packages and Packages.gz. The InRelease and Release.gpg signatures cover the same metadata. See Architecture for the build and signing flow.

Compatibility notes

  • Bash 3.2 or newer is required; the macOS system Bash should work.
  • The APT package is architecture all and depends only on bash; external tools come from your distribution.
  • On the RHEL family, EPEL may be needed for arp-scan, iftop and nethogs.
  • nethogs is Linux-focused and may not work on macOS.
