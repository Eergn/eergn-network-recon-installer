TLS inspection

Inspect one TLS endpoint's handshake and certificate with OpenSSL, then decide whether a broader configuration assessment with testssl.sh is warranted.

Purpose

Answer focused questions about a TLS service: what certificate is presented, which chain is sent, what protocol and cipher are negotiated, and whether the endpoint supports known-weak configurations. This is not a generic web vulnerability scan.

Prerequisites

  • Installed group tls (openssl and testssl.sh).
  • Authorization to connect to the endpoint and, for testssl.sh, to run active configuration checks.
  • The correct hostname for SNI. Connecting by IP can select the wrong virtual host.

Step 1 — inspect one handshake with OpenSSL

openssl s_client -connect lab.example.internal:443 \
  -servername lab.example.internal </dev/null

-connect host:port opens a TLS connection. -servername sets the SNI hostname, which is essential on shared hosting. Redirecting /dev/null into s_client closes stdin immediately so the command exits instead of waiting for interactive input.

To inspect the certificate fields in a readable form:

openssl s_client -connect lab.example.internal:443 \
  -servername lab.example.internal </dev/null 2>/dev/null \
  | openssl x509 -noout -subject -issuer -dates -fingerprint -sha256

The x509 command reads the PEM certificate from the handshake. -noout suppresses the encoded certificate body. -dates shows validity; -fingerprint -sha256 shows a certificate fingerprint.

Step 2 — see the chain the server sends

openssl s_client -connect lab.example.internal:443 \
  -servername lab.example.internal -showcerts </dev/null

-showcerts prints every certificate in the chain sent by the server, not just the leaf. A server may omit an intermediate certificate; clients with cached intermediates may still succeed while others fail. This is a common cause of "works in my browser, fails in curl" reports.

Step 3 — check non-HTTP TLS with STARTTLS

openssl s_client -starttls smtp -connect mail.example.internal:25 \
  -servername mail.example.internal </dev/null

openssl s_client -starttls imap -connect mail.example.internal:143 \
  -servername mail.example.internal </dev/null

-starttls protocol upgrades a plaintext protocol to TLS. The exact protocol name must match what OpenSSL supports. This is useful for mail, LDAP and other services; it does not make the service a web endpoint.

Step 4 — run a bounded testssl.sh assessment

# Faster pass first; still active
testssl.sh --fast lab.example.internal:443

# Protocol and cipher configuration
testssl.sh --protocols lab.example.internal:443
testssl.sh --server-defaults lab.example.internal:443

--fast reduces the test set. --protocols checks which TLS/SSL protocol versions are offered. --server-defaults shows the server's default picks. A full run without a narrowing option performs many checks and can take noticeably longer.

Active and sometimes noisy

testssl.sh opens many connections and may trigger IDS/IPS or rate limits. It is not a passive observation. Use --ids-friendly only when appropriate for the scope; do not use stealth options to evade controls you are not authorized to test.

Step 5 — save structured output

mkdir -p ~/engagements/lab-2026-10-29/raw
testssl.sh --fast --jsonfile ~/engagements/lab-2026-10-29/raw/tls-lab.json \
  --severity HIGH lab.example.internal:443

openssl s_client -connect lab.example.internal:443 \
  -servername lab.example.internal -showcerts </dev/null \
  > ~/engagements/lab-2026-10-29/raw/tls-handshake.txt 2>&1

--jsonfile writes findings to a JSON file. --severity HIGH filters lower-severity findings from CSV/JSON output; it does not make the scan less active. Check the generated file path and version-specific format before parsing it.

Reading the results

ObservationWhat it meansWhat it does not prove
Certificate subject / SAN mismatchThe name you connected to is not listed in the certificateThat the service is malicious or compromised
Expired or not-yet-valid certificateValidity dates do not cover the current timeThat traffic was intercepted
Missing intermediateThe server did not send a full chainThat the leaf certificate is invalid everywhere
Old protocol offeredA deprecated TLS/SSL version is enabledThat an exploitable vulnerability exists
Weak cipher reportedA cipher considered weak is offeredThat it is negotiated by default or practically exploitable
HSTS or header findingAn HTTP policy header is missing or misconfiguredA direct TLS compromise

testssl.sh reports severities and findings. Treat them as configuration evidence. Confirm impact in context, and do not present a scanner finding as a confirmed vulnerability without validation.

Advanced usage

# Test a specific port or a URL
testssl.sh lab.example.internal:8443
testssl.sh https://lab.example.internal/

# Skip the banner in scripted output
testssl.sh --quiet --fast lab.example.internal:443

# Use a specific OpenSSL binary
testssl.sh --openssl /usr/bin/openssl --fast lab.example.internal:443

The URI can be host, host:port, or an HTTPS URL. The URI must be the last argument. See the testssl.sh reference for the option table.

Troubleshooting

SymptomWhat to check
s_client: connect: Connection refusedWrong host/port, service down, or firewall
no peer certificate availableNot a TLS service, STARTTLS required, or handshake failed
Browser works but s_client failsMissing SNI, missing intermediate, or a client-specific trust store difference
testssl.sh: command not foundTLS group not installed, or the Git fallback failed; try sudo eergn-recon-installer -t tls --force
Scan is very slowFull test set; use --fast or a narrower check, and verify the target is reachable

Security considerations

  • TLS inspection connects to the real endpoint. Use the correct SNI and avoid scanning third-party infrastructure without permission.
  • Certificate details, internal hostnames and configuration findings are sensitive assessment data.
  • Do not use downgrade or evasion options to bypass security controls outside an authorized test.
  • Upstream testssl.sh is a separate project under its own license; this installer does not modify or endorse it.
